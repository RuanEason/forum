# 论坛项目备份、迁移与回滚说明

基准日期：2026-08-17  
适用项目：`E:\website` 论坛项目

## 使用边界

- 生产数据库只使用 `prisma migrate deploy`，禁止使用 `prisma db push`。
- 数据库变更必须遵循兼容式迁移：先增加字段或表，再部署兼容代码，完成回填和验证后，最后清理旧逻辑。
- 回滚优先回滚应用代码；数据库迁移原则上使用向前修复迁移。只有确认数据损坏或不可逆兼容问题时，才评估恢复数据库备份。
- 下面的命令只使用占位符，不把生产连接串、密钥或 COS 凭据写入仓库。

## 发布前备份清单

发布负责人必须在发布记录中附上以下证据：

1. MySQL 最近一次可用备份的时间、保留期和恢复演练结果。
2. Redis 当前持久化模式（RDB/AOF 或托管服务快照）、最近一次快照时间和恢复演练结果。
3. COS 存储桶版本控制、生命周期规则、跨地域/异地备份（如套餐支持）及对象恢复验证结果。
4. 当前发布版本、待执行 Prisma migration 名称和回滚负责人。

如果以上任一项没有证据，发布状态必须保持为“待确认”，不能宣称已经具备生产回滚能力。

## MySQL 备份与恢复

### 备份

生产环境优先使用云数据库的自动备份和 binlog/PITR。需要额外生成逻辑备份时，在受控备份机执行：

```bash
mysqldump \
  --single-transaction \
  --routines \
  --events \
  --triggers \
  --hex-blob \
  --set-gtid-purged=OFF \
  --databases <database_name> > <backup_directory>/forum-<timestamp>.sql
```

备份完成后必须校验文件大小和校验和，并把备份文件存放到与生产主库隔离的位置。不要把备份文件提交到 Git 或放在应用静态目录。

### 恢复演练

在隔离的恢复库执行恢复，不直接覆盖生产库：

```bash
mysql \
  --host=<host> \
  --port=<port> \
  --user=<user> \
  --password \
  < <backup_directory>/forum-<timestamp>.sql
```

恢复后执行 Prisma schema 校验、关键表行数抽样和应用只读健康检查。恢复演练必须记录耗时、缺失对象和可接受的数据时间点。

## Prisma 迁移与回滚

### 迁移前

```bash
npx prisma validate
npx prisma migrate status
```

确认工作区干净、备份证据齐全，并核对待发布 migration 是否只包含本节点允许的变更。

### 生产迁移

```bash
npx prisma migrate deploy
```

迁移后检查应用启动、关键读写接口和 Prisma migration 状态。禁止在生产环境用 `npx prisma db push` 代替迁移。

### 应用代码回滚

1. 停止继续发布并保留故障版本日志。
2. 将流量切换到上一个已验证的不可变构建产物。
3. 如果没有可用构建产物，使用 `git revert <commit>` 生成反向提交并重新走构建、测试和发布流程。
4. 重新执行 TypeScript、Prisma、测试和 ESLint 检查，并记录结果。

不要通过删除 migration 文件、修改已执行 migration 或强制重写共享分支历史来回滚生产数据库。

### 数据库回滚

- 优先编写兼容性的向前修复 migration。
- 只有向前修复无法阻止数据损坏时，才在变更负责人批准后，从已验证备份恢复到临时库，确认数据范围后再制定生产恢复方案。
- 恢复数据库后，必须重新执行应用版本兼容性检查，并核对 COS 对象引用、用户登录状态和关键业务数据。

## Redis 备份与恢复

- 生产 Redis 必须启用并记录托管服务快照或 RDB/AOF 持久化策略；仅依赖应用进程内存不算备份。
- 快照、AOF 文件和恢复演练结果必须存放在与 Redis 实例隔离的位置。
- 自建 Redis 可使用受控运维窗口执行 `BGSAVE`，并通过 `LASTSAVE` 检查快照完成时间；托管 Redis 使用服务商提供的快照/恢复能力。
- Redis 数据恢复后先验证限流、会话撤销、通知队列等关键 key 的格式，再恢复应用流量。
- Redis 丢失时，数据库仍必须是用户、帖子和权限等持久数据的事实来源；应用应能在缓存为空时重新建立必要缓存。

## COS 备份与恢复

- COS 对象必须通过存储桶级别的版本控制、生命周期和异地/跨地域策略保护；具体开关状态需在腾讯云控制台或运维平台留存证据。
- 发布前导出或记录图片、附件、原始视频、转码视频、视频封面和用户封面图所使用的前缀与对象清单规则。
- 删除对象前必须确认数据库不再引用，并优先进入延迟清理或恢复窗口。
- 恢复验证至少覆盖一张图片、一个附件和一个视频对象，并检查 CDN URL、权限和内容完整性。
- COS 凭据只从环境变量或密钥管理系统读取，不写入备份说明、日志或测试快照。

## 节点 0 的生产确认边界

本节点在代码仓库内完成备份、迁移和回滚流程说明，并完成环境变量与功能开关约定。生产 MySQL、Redis、COS 的实际快照开关、保留期和恢复演练属于部署环境证据，不能通过本地源码检查代替；上线节点 1 前必须补齐发布记录中的三类备份证据。

当前开发环境使用开发 MySQL 和开发 Redis，开发数据丢失可以接受；Redis 当前主要用于验证码。该结论不适用于生产环境，迁移到生产服务器前仍必须建立生产数据库、Redis 和 COS 的备份、保留期及恢复演练记录。
