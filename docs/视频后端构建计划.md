# 视频后端构建计划

更新日期：2026-02-17  
适用项目：`forum`（Next.js 16 + Prisma + MySQL + COS + 数据万象）

## 1. 目标与约束

### 1.1 目标
1. 支持“视频贴”后端能力：上传、转码、状态查询、发布绑定、播放地址返回。
2. 上传链路使用“前端直传 COS 分片上传 + 临时密钥 STS”。
3. 使用数据万象工作流做多码率 HLS 输出（480p/720p/1080p + master m3u8）。
4. 保留现有帖子评论体系（`PostComments`）不改。

### 1.2 强约束
1. 不允许 Next API 中转视频文件本体。
2. 后端只做鉴权、签发临时凭证、写入状态、接收回调、返回播放信息。
3. 所有上传对象需限定到用户私有前缀，避免越权写入。

### 1.3 非目标（第一期不做）
1. 视频审核（涉政涉黄等）自动封禁策略。
2. 字幕上传与转码。
3. 弹幕系统。
4. 多视频合辑贴。

## 2. 总体架构

1. 前端请求后端 STS 接口，获取短期上传凭证和对象 Key。
2. 前端使用 COS SDK `sliceUploadFile` 直传 `videos/raw/...`。
3. 上传成功后前端调用后端“提交上传完成”接口。
4. 数据万象工作流基于 `videos/raw/` 自动触发，产出 HLS。
5. 数据万象回调后端，后端更新视频状态为 `READY/FAILED`。
6. 前端轮询状态接口，`READY` 后允许发布视频贴。
7. 发帖时提交 `videoAssetId`，后端校验归属与状态后落库。

## 3. 云侧前置配置（需和后端联调确认）

1. COS 目录约定：
   1. 原始文件：`videos/raw/{userId}/{yyyy}/{MM}/{uuid}.{ext}`
   2. 转码输出：`videos/hls/...`
   3. 封面图：`videos/poster/...`
2. 数据万象工作流触发路径：`videos/raw/`。
3. 工作流输出路径不得与输入路径重叠，防止重复触发。
4. CDN 域名可访问 `.m3u8` 和分片文件（`.ts`/`.m4s`）。
5. COS CORS 允许前端域名进行分片上传与播放请求（`GET/PUT/POST/HEAD/OPTIONS`）。

## 4. 数据库改造（Prisma）

## 4.1 新增枚举

```prisma
enum PostType {
  TEXT
  VIDEO
}

enum VideoStatus {
  INIT
  UPLOADING
  UPLOADED
  PROCESSING
  READY
  FAILED
  DELETED
}
```

## 4.2 新增模型

```prisma
model VideoAsset {
  id                 String      @id @default(cuid())
  ownerId            String
  owner              User        @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  post               Post?

  region             String
  rawObjectKey       String      @unique
  rawUrl             String
  mimeType           String
  fileSize           BigInt

  hlsMasterObjectKey String?
  hlsMasterUrl       String?
  coverObjectKey     String?
  coverUrl           String?

  durationSec        Float?
  width              Int?
  height             Int?
  bitrateKbps        Int?

  workflowRunId      String?
  status             VideoStatus @default(INIT)

  createdAt          DateTime    @default(now())
  updatedAt          DateTime    @updatedAt

  @@index([ownerId, status])
  @@index([createdAt])

```

## 4.3 调整 Post 模型

```prisma
model Post {
  id          String     @id @default(cuid())
  title       String?
  content     String     @db.Text
  postType    PostType   @default(TEXT)
  videoId     String?    @unique
  video       VideoAsset? @relation(fields: [videoId], references: [id], onDelete: SetNull)
  // ... 保持现有字段不变

```

说明：`content` 继续保留为必填字符串，视频贴可传空字符串 `""`。

## 5. 后端接口设计（/api/video/*）

## 5.1 `POST /api/video/sts`

用途：签发临时上传凭证并创建 `VideoAsset(INIT)` 记录。  
鉴权：必须登录。

请求示例：

```json
{
  "fileName": "demo.mp4",
  "fileSize": 734003200,
  "mimeType": "video/mp4"
}
```

响应示例：

```json
{
  "videoAssetId": "clx...",
  "objectKey": "videos/raw/u_123/2026/02/uuid.mp4",
  "bucket": "forum-1398498368",
  "region": "ap-guangzhou",
  "cdnBaseUrl": "https://cdn.zyg2024.top",
  "credentials": {
    "tmpSecretId": "...",
    "tmpSecretKey": "...",
    "sessionToken": "...",
    "startTime": 1739779200,
    "expiredTime": 1739781000
  },
  "constraints": {
    "maxSizeBytes": 2147483648,
    "allowedMimeTypes": ["video/mp4", "video/quicktime", "video/x-msvideo"]
  }
}
```

后端要点：
1. 校验大小、类型、登录态。
2. 生成受限策略，仅允许写入当前用户的 `videos/raw/{userId}/` 前缀。
3. 记录 `VideoAsset` 初始状态为 `UPLOADING`。

## 5.2 `POST /api/video/commit`

用途：前端直传成功后，通知后端进行对象存在性确认并进入待处理状态。  
鉴权：必须登录。

请求示例：

```json
{
  "videoAssetId": "clx...",
  "objectKey": "videos/raw/u_123/2026/02/uuid.mp4",
  "etag": "\"abc...\""
}
```

处理逻辑：
1. 校验 `videoAsset` 归属。
2. `HEAD Object` 确认文件存在、大小和类型有效。
3. 更新状态：`UPLOADED -> PROCESSING`。
4. 返回状态给前端开始轮询。

## 5.3 `POST /api/video/callback`

用途：接收数据万象工作流回调并落库。  
鉴权：建议 `?token=CI_CALLBACK_TOKEN` + 请求体结构校验 + 幂等处理。

处理逻辑：
1. 校验 token。
2. 解析回调中的源文件 Key、工作流运行 ID、任务状态。
3. 成功时提取 `master.m3u8` 对象路径和封面图路径，写入 `hlsMasterUrl/coverUrl`。
4. 更新状态：
   1. 成功：`READY`
   2. 失败：`FAILED` + `errorCode/errorMessage`
5. 记录事件日志，避免重复回调导致脏写。

## 5.4 `GET /api/video/:id`

用途：前端轮询视频处理状态。  
鉴权：登录后仅本人可查；帖子公开后可匿名读 `READY` 基本信息。

响应示例：

```json
{
  "id": "clx...",
  "status": "READY",
  "hlsMasterUrl": "https://cdn.zyg2024.top/videos/hls/master/xxx.m3u8",
  "coverUrl": "https://cdn.zyg2024.top/videos/poster/xxx.webp",
  "durationSec": 123.45,
  "width": 1920,
  "height": 1080
}
```

## 6. 发帖接口改造（/api/post）

1. `POST /api/post` 新增字段：

```json
{
  "postType": "VIDEO",
  "videoAssetId": "clx..."
}
```

2. 服务端校验：
1. `postType=VIDEO` 时，`videoAssetId` 必填。
2. `videoAsset.ownerId` 必须等于当前用户。
3. `videoAsset.status` 必须为 `READY`。
4. 一个 `VideoAsset` 只能绑定一个 `Post`（唯一约束）。

3. 列表与详情查询增加 `video` 字段，返回 `hlsMasterUrl` 与 `coverUrl`。

## 7. 状态机

`INIT -> UPLOADING -> UPLOADED -> PROCESSING -> READY`  
失败分支：`UPLOADING/PROCESSING -> FAILED`  
删除分支：`READY/FAILED -> DELETED`

状态变更责任：
1. `sts`：置 `UPLOADING`
2. `commit`：置 `PROCESSING`
3. `callback success`：置 `READY`
4. `callback fail`：置 `FAILED`

## 8. 安全要求

1. STS 最小权限策略：仅允许用户前缀下分片上传相关动作。
2. 临时凭证有效期建议 30 分钟。
3. 回调接口必须有服务端密钥校验，不接受匿名公网随意写状态。
4. 所有对象 Key 由后端生成，前端不得自定义跨用户路径。
5. 对外仅暴露 CDN URL，不暴露永久密钥。

## 9. 运维与清理

1. 定时任务每日清理：
   1. 超过 24 小时仍 `UPLOADING` 的脏记录。
   2. 超过 7 天且未绑定帖子的 `READY` 视频（可选）。
2. 帖子删除策略：
1. 第一版先软删 DB 状态，不立即删 COS 对象。
2. 夜间异步回收对象，避免误删影响回滚。
3. 日志监控：
1. STS 签发量
2. 回调失败率
3. 转码平均时长
4. `FAILED` 状态占比

## 10. 开发拆分（建议）

## 阶段 A：基础能力（1-2 天）
1. Prisma 模型与迁移。
2. `POST /api/video/sts`
3. `POST /api/video/commit`
4. `GET /api/video/:id`

## 阶段 B：处理闭环（1 天）
1. `POST /api/video/callback`
2. 状态机完整落库
3. 幂等与错误处理

## 阶段 C：帖子集成（1 天）
1. `/api/post` 支持视频贴字段
2. 列表/详情返回 video 信息
3. 权限与唯一绑定校验

## 阶段 D：稳定性（0.5-1 天）
1. 清理任务
2. 监控日志
3. 灰度开关与回滚开关

## 11. 联调验收清单

1. 前端拿 STS 后可直传 1GB+ 视频，后端无中转流量。
2. 上传后 `commit` 成功，状态进入 `PROCESSING`。
3. 数据万象回调成功后状态变 `READY`，可拿到 `master.m3u8`。
4. 视频贴发布成功，帖子详情可读取视频信息。
5. 非本人 `videoAssetId` 绑定被拒绝。
6. 转码失败可返回 `FAILED` 且错误可追踪。
